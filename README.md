# ROM — Vercel + Neon + Gmail

Сайт размещается на Vercel, база данных Neon Postgres, подтверждение почты — через Gmail SMTP и шестизначный код. Supabase и Resend не нужны.

## Обновление
1. Замените файлы проекта в GitHub содержимым этой папки `rom-site`.
2. В Vercel → Project → Settings → Environment Variables добавьте:
   - `DATABASE_URL` — строка подключения Neon (уже настроена, не меняйте).
   - `GMAIL_USER` — адрес отдельного Gmail-аккаунта для писем.
   - `GMAIL_APP_PASSWORD` — **пароль приложения Google**, НЕ обычный пароль аккаунта. Включите двухэтапную аутентификацию и создайте пароль приложения в настройках Google Account → Security → App passwords. Уберите пробелы при вставке.
3. Для `GMAIL_APP_PASSWORD` выберите тип Secret. Все переменные должны быть доступны в Production.
4. В Vercel → Deployments выполните Redeploy последней версии после сохранения переменных.
5. Войдите в ROM, откройте «Аккаунт» или «Настройки», нажмите «Отправить код», затем введите шестизначный код в форму.

## Важно
- Не требуется повторно выполнять `db/postgres.sql`, если таблицы уже созданы. Новых таблиц нет: используется существующая `email_tokens`.
- Удалите неиспользуемые `RESEND_API_KEY`, `EMAIL_FROM`, `PUBLIC_URL` из Vercel, когда убедитесь, что новая версия работает.
- Gmail SMTP — простой вариант для небольшого проекта, но Google может ограничивать автоматические отправки или блокировать подозрительную активность. Для массовой регистрации понадобится специализированная почтовая служба.
- Код действует 10 минут. Повторный запрос ограничен примерно одной минутой.
- Новые аккаунты могут входить до подтверждения, но сервер запрещает им оценки и рецензии.
- Никогда не публикуйте `DATABASE_URL` и `GMAIL_APP_PASSWORD` в GitHub.

## ROM Studio: артисты и заявки (v5)

После обновления файлов **обязательно** один раз выполни `db/migration_004_artist_submissions.sql` в Neon → SQL Editor. Миграция добавляет `users.is_artist` и таблицу `track_submissions`; существующие аккаунты, релизы и оценки не удаляются.

**Как включить панель тестирования:** назначь себе администратора через Neon SQL Editor (подставь собственный ник):

```sql
UPDATE users SET is_admin = TRUE WHERE username = 'ТВОЙ_НИК';
```

Выйди и зайди в аккаунт заново или обнови страницу. Открой аватар → Аккаунт → «Панель тестирования». Там можно выдавать и снимать зелёную нотку пользователям и просматривать заявки. Админ не получает нотку автоматически: роль артиста выдаётся отдельно.

**Артист:** зелёная нотка отображается в профиле, меню и возле имени автора рецензии. Артисту с подтверждённой почтой доступна кнопка «♫ Загрузить трек» слева от аватара. Форма принимает ссылки на аудио и обложку по HTTPS, а не бинарные файлы. Заявки сохраняются в Neon со статусом `pending`; администратор может одобрить или отклонить. **Одобрение пока не создаёт релиз автоматически** — это отдельный следующий этап.

**Оценки и рецензии:** уже сохраняются в Neon через `/api/ratings` и `/api/reviews`; для записи сервер требует `email_verified = TRUE`. На странице релиза есть формы оценки и рецензии. Для теста добавь релиз в базу, если каталог пуст.

**Изображения:** аватары и обложки сейчас указываются HTTPS-ссылками, а не загружаются на Vercel. Добавлен предпросмотр обложки при подаче трека. Для загрузки локальных файлов в будущем понадобится объектное хранилище (например, Vercel Blob) и ограничения по формату и размеру. Не вставляй в поля ссылки на непроверенные ресурсы.

**Безопасность:** права артиста и администратора проверяются в API, а не только кнопками интерфейса. Не публикуй `DATABASE_URL`, `GMAIL_APP_PASSWORD` или иные секреты в GitHub. Для реального публичного запуска ещё нужны ограничения запросов, проверка загружаемого контента и антиспам.


## v6 — Реальная загрузка файлов

1. Neon SQL Editor: выполни `db/migration_005_media.sql` **один раз** (после migration_004).
2. Vercel → Storage → Create Database → **Blob** → подключи Blob store к проекту ROM. Убедись, что в проекте появилась `BLOB_READ_WRITE_TOKEN` (секретная переменная).
3. Загрузи обновлённый проект на GitHub, дождись нового деплоя.
4. Для добавления релиза аккаунт должен иметь `is_verified` или `is_admin`; для отправки трека — `is_artist` и подтверждённую почту.
5. На формах укажи имя артиста, featuring (если есть), обложку PNG/JPG до 4 МБ и аудио MP3/FLAC/WAV до 40 МБ. Загрузка выполняется **напрямую из браузера в Vercel Blob**, поэтому лимит тела запроса Vercel Functions не мешает загрузке 40 МБ.

**Внимание:** Blob используется в публичном режиме, поэтому ссылки на загруженные аудио и обложки доступны всем, у кого есть URL. Не загружай приватные или чужие материалы без разрешения. Отправленные файлы остаются в Blob даже если сохранение записи в Neon завершилось ошибкой; такие файлы можно удалить вручную в Storage. Vercel Blob может потребовать включённого биллинга/доступного лимита — проверь условия тарифа.

`@vercel/blob` используется на сервере; браузерный модуль загружается с esm.sh. При необходимости позже соберём его локально в bundle.


## v7 — Тип релиза и треклист

Выполни **один раз** `db/migration_006_release_types.sql` в Neon SQL Editor после предыдущих миграций. Существующие данные сохраняются. Затем обнови файлы GitHub и дождись деплоя Vercel.

Форма «Добавить релиз» поддерживает Сингл (1 трек), автоматически Мульти-сингл (2 трека), EP и Альбом (1–30 треков), индивидуальные названия, featuring и аудиофайлы MP3/FLAC/WAV до 40 МБ **на каждый трек**. Обложка общая до 4 МБ. Каждый файл загружается напрямую в Vercel Blob, а ссылки и порядок треков сохраняются в Neon. Для EP/альбома количество треков сейчас не ограничено жанровыми стандартами — от 1 до 30.

Внимание: большие релизы могут расходовать квоту Vercel Blob. При ошибке публикации уже загруженные файлы могут остаться в Blob и потребовать ручной очистки. Существующая форма «Отправить трек» для артистов пока остаётся однотрековой.
