# ROM Studio v26 — заявки, ID, реальная публикация

Основа: ROM Studio v25. Vercel + Neon + Gmail + Vercel Blob остаются без изменений.

## Порядок обновления

1. **Сделайте резервную копию Neon** перед применением миграции.
2. В Neon → SQL Editor выполните **целиком и один раз** файл `db/migration_009_ids_requests_publication.sql`. Эта миграция не удаляет релизы и аккаунты.
3. Замените исходники в GitHub содержимым ZIP и выполните деплой Vercel.
4. После деплоя проверьте «Настройки» → «Личный ID» (шесть цифр) → «Смена никнейма».
5. Проверьте колокольчик администратора и раздел «Смена ника» в панели управления. Выдача верификации и роли артиста теперь работает только через шестизначный публичный ID.
6. Проверьте публикацию **тестовой** заявки: после «Одобрить и опубликовать» созданный релиз должен отображаться в каталоге. Публикация в одной транзакции сохраняет альбом, исполнителя, треки и связь с заявкой.

## Важные уточнения

- Внутреннее поле `users.id` и все внешние ключи **не изменены**. `users.public_id` — отдельный шестизначный ID; ID не переиспользуются в пределах диапазона 100000–999999.
- Верификация не требует смены почты и не подтверждает её автоматически.
- При смене ника через запрос администратор видит исходный ник, публичный ID и новый ник; если ник занят, одобрение блокируется.
- При публикации **старых** одобренных заявок без `published_album_id` доступна кнопка «Опубликовать», чтобы исправить прежнее поведение, когда статус менялся без создания релиза.
- Одну заявку невозможно опубликовать дважды через новый API благодаря блокировке строки и `published_album_id`.
- Отклонённые заявки нельзя одобрить повторно: артист отправляет новую.
- Новая версия не переносит файлы в Blob и не удаляет старые оценки, новости или рецензии.
- SQL нужно выполнить **до деплоя**, иначе API запросов/уведомлений будут возвращать ошибки из-за отсутствующих таблиц и полей.
