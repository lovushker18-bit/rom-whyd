# ROM v27 — Случайные шестизначные ID

В v26 шестизначные ID выдавались последовательно. В v27 они **случайные**, например 583174, 926041, 147608. Повторы не допускаются. У каждого аккаунта остаётся один постоянный ID после этой миграции.

## Установка

1. В Neon → SQL Editor запустите `db/migration_010_random_public_ids.sql` **после** `migration_009_ids_requests_publication.sql`.
2. Для v27 менять код Vercel необязательно — новый ID генерируется на стороне PostgreSQL по умолчанию при регистрации.
3. В SQL Editor проверьте `SELECT username, public_id FROM users ORDER BY id;`.

**Важно:** миграция один раз заменит ранее выданные последовательные публичные ID. Если вы уже сообщали кому-то старый шестизначный ID, нужно сообщить новый. Внутренние `users.id` остаются прежними, так что оценки, рецензии, релизы и авторизации не затронуты. Повторный запуск файла не изменит ID снова.

`UNIQUE` индекс и транзакционная блокировка обеспечивают отсутствие повторов. Используемая функция `random()` предназначена для публичных идентификаторов, а не секретных кодов доступа или токенов.
